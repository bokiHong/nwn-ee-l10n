# 从零把任意 `.mod` 汉化 —— 一步一命令（实战手册）

> 写给"想自己动手"的你。全程不需要 NWN MultiLang。
> 所有路径按你机器的实际情况写好了，可以直接复制粘贴。
> 预计：第 1 章跑完约 15~30 分钟（含人工看结果），熟练后更多。

---

## 0. 先记三条安全铁律

1. **永远不要用 NWN MultiLang 的 "Import to"。** 它是「先打开目标文件并截断 → 再写入」，
   一旦崩溃目标文件就变成 **0 字节**（2026-10-07 你已亲身踩过一次，原始 Ch1.mod 就是这么没的）。
2. **动手前先体检 + 干跑**：`modl10n.check` 看文件健康，`--dry-run` 零花费走一遍全流程。
3. **要覆盖原件只用 `--inplace`**：它会**自动先备份**成 `<名字>.orig-backup` 并校验大小。
   本工具所有写出都是**原子写**（先写 `.tmp-writing` 再替换），结构上不可能再产生 0 字节文件。

## 1. 一次性准备（只做一次，约 3 分钟）

### 1.1 确认 Python 环境 + 依赖（顺便给所有 mod 做体检）

```powershell
cd C:\nwn-ee-l10n
python -m modl10n.check "%USERPROFILE%\Documents\Neverwinter Nights\modules"
```

期望输出（每个 mod 一行 ✅，并显示"是否已汉化"）：

```
✅ Swordflight - Chapter One.mod     11182300 字节  条目 1934   【未检出中文】
✅ Swordflight - Chapter One_zh.mod  11815140 字节  条目 1934   【已汉化 5722 处】
```

> 若看到 ❌ 或"0 字节"，**先别翻译**，把输出发我。

### 1.2 放 API Key（三选一，推荐第一种）

```powershell
# ① 临时环境变量（关掉窗口就失效，最省事）
$env:DEEPSEEK_API_KEY = 'sk-你的key'

# ② 写进文件（长期有效，工具会自动读）
'sk-你的key' | Out-File -Encoding utf8 C:\nwn-ee-l10n\modl10n\.api_key
```

> 工具读 key 的顺序：`--api-key` 参数 → 环境变量 `DEEPSEEK_API_KEY` → `modl10n\.api_key` → `sf01\.api_key`

### 1.3 确认 nwnsc 与游戏安装目录（工具会自动找，不用管）

```
nwnsc   : %USERPROFILE%\Documents\Neverwinter Nights\hak\nwnsc.exe
安装目录: D:\Program Files (x86)\Steam\steamapps\common\Neverwinter Nights   ← 从 nwn.ini 自动反推
```
找不到时手动指定：`--nwnsc <路径> --install-dir <路径>`

## 2. 翻译一章（以 Chapter Two 为例，四步）

### 第 1 步：零花费看清工作量

```powershell
$M = "%USERPROFILE%\Documents\Neverwinter Nights\modules\Swordflight - Chapter Two.mod"
python -m modl10n.pipeline --mod "$M" --extract-only --outdir ".\out_ch2"
```

期望输出：
```
资源 6322 个；可译单元 29573 条；内容去重后 11911 条
其中【疑似显示文本·字符串变量赋值】19 条（已翻译，建议抽查）：
```
- **去重后条数** = 这一章最多要花多少次调用（实际会更少，因为翻译记忆里已有旧译）
- **疑似变量赋值** 是判别器有把握不足的少数条目，翻完抽查一下即可

### 第 2 步：零花费干跑（验证回写与打包链路）

```powershell
python -m modl10n.pipeline --mod "$M" --dry-run --outdir ".\out_ch2"
```
约 5 秒。看两个数字：**回写统计**里 `gff_已替换 / nss_已替换` 不为 0，说明定位正常。
（`--dry-run` 不调 API、不写文件、不重编译 `.ncs`。）

### 第 3 步：冒烟 50 条（花一点点钱，验证真实链路）

```powershell
python -m modl10n.pipeline --mod "$M" --limit 50 --workers 4 --outdir ".\out_ch2" --yes
```

**重点看这一行**：
```
读回校验：比对 29573 条，不一致 0 条
```
- `不一致 0 条` → 链路正确，可以放心全量
- `不一致 > 0` → **别装进游戏**，把报告发我
- 报告文件：`out_ch2\Swordflight - Chapter Two.report.json`

产物 `out_ch2\Swordflight - Chapter Two_zh.mod` 只有 50 句是中文，**这是冒烟残章，别拿去玩**。

### 第 4 步：全量（可随时 Ctrl+C，重跑自动续传）

```powershell
python -m modl10n.pipeline --mod "$M" --workers 5 --outdir ".\out_ch2" --yes
```

- 中断 / 关窗口都没关系：**已翻译的都记在 `modl10n\tm.sqlite` 里**，重跑不会重复付费
- 想看进度：屏幕上每翻一条打印一行 `[i/N] …`

### 第 5 步：装进游戏

```powershell
Copy-Item ".\out_ch2\Swordflight - Chapter Two_zh.mod" `
          "%USERPROFILE%\Documents\Neverwinter Nights\modules\" -Force
```
然后启动游戏 → 新游戏 / 载入 → 选 **Swordflight - Chapter Two_zh**。

> 想让**原始文件名**也变中文（例如想在 mod 列表里只看到一个条目）：
> ```powershell
> python -m modl10n.pipeline --mod "$M" --inplace --workers 5 --yes
> # 原件会先被备份成 "Swordflight - Chapter Two.mod.orig-backup"
> ```

## 3. 批量跑多章（顺序跑，越后面越省）

```powershell
$D = "%USERPROFILE%\Documents\Neverwinter Nights\modules"
python -m modl10n.batch --mods `
  "$D\Swordflight - Chapter Two.mod" `
  "$D\Swordflight - Chapter Three.mod" `
  "$D\Swordflight - Chapter Four.mod" `
  "$D\Swordflight - Chapter Five.mod" `
  --workers 5 --outdir ".\out_swordflight" --yes
```

- 四章**共用一份翻译记忆**：Ch3 会白拿 Ch1+Ch2 的译文，Ch5 能白拿 30% 以上
- 每章独立打包 + 独立读回校验，**一章失败不影响其他**
- 汇总报告：`out_swordflight\batch_report.json`
- 中途想停：`Ctrl+C`，下次重跑接着来

## 4. 译名统一（每章跑完后做一次，**0 花费**）

新章节会出现新人名，模型可能翻译得不统一。闭环四步：

### 第一步：挖候选（看这章出现了哪些新专名）

```powershell
python -m modl10n.terms mine --tm modl10n\tm.sqlite --out ".\out_ch2\term_candidates.csv"
```
输出示例：`从 3354 条记忆里挖出 427 个候选`。用 Excel 打开 CSV，
**只挑人名/地名/神祇/法术器物名**（`Bag=袋子`、`Ghoul=食尸鬼` 这类普通名词不要）。

### 第二步：把挑中的填进术语表

⚠ **别再编辑 `modl10n\glossary.json`** —— 它从 Sprint 4 起只是**冻结快照**（2026-10-08），
改了**不生效** ✗（术语真源是 `modl10n\tm.sqlite` 的 `term` 表）。正确做法：

**① 双击 `启动术语库.bat`** → 「➕ 新增术语」填 `en / zh / type / required` → 保存 ✓
（改动只写 `term` 表，同一个 `en` 只会留一条 active）

**② 或者用 GUI 批量导入**：术语库编辑器支持粘贴**表格 / `N.英文 中文` 编号列表** ✓

**③ 命令行等价物**：`python -m l10n terms --action import-legacy --glossary <你的json>`

- `required: true` = 必守（译前写进【固定译名·必须使用】，译后**宽容校验**）
- `required: false` = 只作建议（**不确定就用这个**；`Helm`（神祇）这种与普通名词冲突的词尤其要设 false，否则 `Helm of Awareness` 会被误命中）

**改完记得重建命中缓存**：`python -m l10n terms --action index-terms`（约 4 分钟，
否则「术语违规检查」用的还是旧缓存 ✗）

### 第三步：体检（看已有译文有没有漂移）

```powershell
python -m modl10n.terms audit --tm modl10n\tm.sqlite --glossary modl10n\glossary.json
```
输出分两栏：**【必守】需要修** 和 **【建议】仅供参考**。只有必守那一栏要处理。

### 第四步：就地回订（**0 次 API 调用**）

```powershell
# 先预览
python -m modl10n.terms fix --tm modl10n\tm.sqlite --glossary modl10n\glossary.json --dry-run
# 真正执行
python -m modl10n.terms fix --tm modl10n\tm.sqlite --glossary modl10n\glossary.json
# 重新打包（0 调用）
python -m modl10n.pipeline --mod "…\Swordflight - Chapter Two.mod" --outdir ".\out_ch2" --yes
```

**若 audit 之后还有残留**：把残留的错译补进 `modl10n\term_variants.json`
（格式 `{"错误译法": "规范译法"}`），再跑一次 `fix`。这是**迭代收敛**的过程
（Ch1 实测：第一次 60 条、补一次变体后又 2 条、第三次归零）。

## 4.5 润色／审校（人工修改我翻好的译文）

**原理（很重要，先看这段）**：译文只存在**翻译记忆库** `modl10n\tm.sqlite` 里，
打包时脚本是从记忆库取译文的。所以**直接改 txt 文件不会生效** ——
必须把改好的内容**回导记忆库**，再重新打包（后者 0 花费）。

```powershell
# ① 导出审校表（TSV，Excel / 记事本都能开；带 BOM，Excel 不会把中文显示成乱码）
python -m modl10n.review export --mod "$M" --out ".\审校表.tsv"

#    只要一部分？按文件类型 / 关键词筛，或者分块（每块 200 条）
python -m modl10n.review export --mod "$M" --out ".\第1块.tsv" --limit 200
python -m modl10n.review export --mod "$M" --out ".\对话.tsv"  --fname ".dlg"
python -m modl10n.review export --mod "$M" --out ".\某角色.tsv" --filter "扎拉拉"

# ② 只改「现译」这一列，保存为 UTF-8
#    其余列不要动（key / 英文原文 列若被改动，回导时会检测出来并跳过该行）

# ③ 回导（先 dry-run 看会改多少条）
python -m modl10n.review apply --file ".\审校表.tsv" --dry-run
python -m modl10n.review apply --file ".\审校表.tsv"
#    改过的条目会标为 status=manual —— 机器翻译永远不会再覆盖你的润色

# ④ 重新打包（0 次 API 调用）
python -m modl10n.pipeline --mod "$M" --outdir ".\out_ch1" --yes
```

审校表长这样（Tab 分隔，一行一条**不重复**文本）：

| key | 英文原文 | 现译 | 状态 | 类型 | 位置 | 字段 | 出现次数 |
|---|---|---|---|---|---|---|---|
| c2dad471… | Test Object | 测试对象 | 已译 | gff | a_testobject001.uti | LocalizedName | 1 |

**三个省力要点**

1. **一行 = 一种"不重复文本"**，同一句话在全文出现多少次都只有一行 —— 改一次全部生效。
   实测：改「阿萨比钥匙」一行，`acdoorkey001.uti` 和 `asabicave001.git` 两处**一起变了**。
2. **分块润色**：`--limit 200 --offset 200` 一块块来，不用一次面对 3000 条。
3. **想让模型重译某几句**（你不想手改）：
   ```powershell
   python -m modl10n.review retranslate --file ".\审校表.tsv" --filter "关键词"
   ```
   这些句会被标为待重译，下次跑 pipeline 时模型会重新翻（会花少量钱）。

**只改一句的最快办法**：用 DB Browser for SQLite 打开 `modl10n\tm.sqlite`，
改 `tm` 表里那条的 `dst`、并把 `status` 改成 `manual`，然后重新打包（0 花费）。
适合零星的临时修补。

## 4.6 可视化编辑器（`mod tool.py`，润色首选）

**双击 `汉化\启动mod编辑器.bat`** 即可开窗（不用敲命令）。

界面：左边是所有**不重复文本**（状态 / 位置 / 译文预览），点一条 →
右上显示英文原文（只读），右下是可编辑的译文。

- 改完按 **Ctrl+Enter** 应用（收进内存），改完一批按 **Ctrl+S 保存到记忆库**
  （保存的条目标为 `manual`，机器翻译永不再覆盖你的润色）
- **文件 → 重新打包**：把改动打进 .mod，**不调用任何 API（0 花费）**；
  想替换原始文件名就选"覆盖原件"（自动备份为 `.orig-backup`）
- 搜索框可搜原文/译文；还有「只看未译/待重译」「只看已改」「资源名含」三种筛选
- 右上角会提示「该文本在本 mod 出现 N 处」—— **改一次，所有出现处一起生效**
- 「标记待重译」只是做记号：要让模型重翻，得用命令行跑 `pipeline`（会产生费用）。
  **本程序的打包按钮永远不会调用 API。**

命令行下同一套功能也在（适合脚本化）：

```powershell
python "mod tool.py" info   "…\X.mod"                 # 看工作量，0 花费
python "mod tool.py" export "…\X.mod" ".\审校表.tsv"   # 导出审校表
python "mod tool.py" apply  ".\审校表.tsv"             # 回导
python "mod tool.py" repack "…\X.mod" --outdir ".\out" # 打包已有译文，0 花费
python "mod tool.py" repack "…\X.mod" --inplace        # 覆盖原件（自动备份）
```

**为什么必须先「保存到记忆库」再「重新打包」**：译文存在 `tm.sqlite` 里，打包是从记忆库
取译文的；本程序**不直接改写 .mod**（那很危险）。打包交给经过验证的 pipeline ——
原子写、覆盖原件前自动备份、打完自动读回校验（不一致必须为 0）。

实测：编辑器改一条 → 保存 → 打包，产物与命令行流程**逐字节相同**。

## 5. 花钱控制速查

| 我想… | 命令 | API 花费 |
|---|---|---|
| 看这一章有多少工作量 | `--extract-only` | **0** |
| 验证回写/打包链路 | `--dry-run` | **0** |
| 只翻接下来 50 条 | `--limit 50` | 约 50 次 |
| 全量翻译 | 直接跑 | 按去重条数 |
| 中断后继续 | 重跑同一条命令 | **只付没翻过的** |
| 重新打包（改过术语/润色后） | 直接跑 | **0** |
| 导出/回导审校表（润色） | `review export` / `review apply` | **0** |
| 让模型重译某几句 | `review retranslate` | 少量（按句数） |
| 术语回订 | `terms fix` | **0** |
| 只想汉化物品/对话，不动脚本 | `--no-nss` | 更少 |
| 完全不想重编译脚本 | `--no-ncs` | 同量（脚本内文本保持英文） |

**记住：费用只取决于"有多少条不重复的整句 × 句子多长"。**
往术语表里加词**不会**让翻译变便宜（这点已实测确认）。

## 6. 出问题怎么办（速查表）

| 症状 | 原因 | 怎么办 |
|---|---|---|
| `.mod` 变成 0 字节 | 用了会"先截断再写"的第三方工具 | `python -m modl10n.check <目录>` 确认；从 `.orig-backup` / `_original\` / 存档副本恢复 |
| 报"替换目标文件失败：拒绝访问" | 目标被游戏占用，或文件带只读属性 | 先退出游戏；只读属性工具会自动清（手工清：右键 → 属性 → 取消只读） |
| 报"备份校验失败" | 磁盘写入异常 | 原件未被改动，检查磁盘空间后重试 |
| 读回校验不一致 > 0 | 回写定位异常 | **别装进游戏**，把 `<名字>.report.json` 发我 |
| 某几个脚本 `.ncs` 编译失败 | 模块自带的旧 include 与当前游戏版本冲突（**与汉化无关**） | 正常。那些脚本保持英文，报告里会列出，游戏可正常运行 |
| `s_library001/002` 编译"失败" | 它们是纯 include（没有 `main`），nwnsc 不产出 `.ncs` | 正常。它们的译文会随引用它们的脚本一起生效 |
| 术语没统一 | 模型没照用规范译名 | `terms audit` → `terms fix`（0 花费） |
| 某句话译得不好/想改 | — | 直接改 `modl10n\tm.sqlite` 里那条的 `dst` 并把 `status` 设为 `manual`（机器永不覆盖），再重跑打包（0 花费） |
| 想看看某 mod 会命中哪些术语 | `python -m modl10n.terms scan --glossary modl10n\glossary.json --mod "X.mod"` | 0 |
| 进度打印里出现 `[重试 x/8]` | 网络抖动/限流 | 正常，指数退避后自动继续 |
| 想彻底重来某个 mod | 删掉 `tm.sqlite` 里对应条目即可（或直接删整个 `tm.sqlite` 重新攒） | — |

## 7. 给"别的模组"用的注意事项

1. **`modl10n` 只管 `.mod` 里的文本**。如果那个模组的文本在 `.hak` / `.tlk`（对话表）/ `.2da` 里，
   本工具看不到 —— 那种要做 TLK 汉化（你之前的 PRC8 就是那类）。
2. **`.mod` 里的 `.bic`（角色模板）/`.sav`（存档模板）** 也会被扫到并翻译其内文本，一般无妨；
   不想要就 `--no-nss`（只处理 GFF）或先 `--extract-only` 看清再决定。
3. **一定要先 `--extract-only`**：不同模组的文本量差别巨大（你 Ch1 是 3,325 条，
   Ch2 是 11,911 条），先看清再决定要不要翻。
4. **翻译记忆是跨模组共用的**：翻过 Swordflight 之后再翻别的模组，凡是重复的句子都免费
   （D&D 模组之间重复度不低）。
5. **别把备份文件喂进去**：`batch` 会自动跳过 `.BAK` / `.prc.BackupMod` / `_zh` / `备份` 结尾的文件。

## 8. 命令参数全表

```
python -m modl10n.pipeline --mod X.mod [选项]
  --sf01 FILE        走路线 A（用 NWN MultiLang 导出的文本）作兜底；默认路线 B（自研抽取）
  --out FILE         指定输出文件路径
  --inplace          覆盖输入的 .mod（自动备份为 <名字>.orig-backup）
  --outdir DIR       产物目录（默认 <mod 所在目录>\汉化产物）
  --workers N        并发路数，默认 5
  --limit N          只翻"接下来 N 条未译"（可反复执行逐步推进）
  --tm FILE          翻译记忆 sqlite（默认 modl10n\tm.sqlite）
  --glossary FILE    术语源：*.sqlite -> term 表（**默认**，最新真源）；
                     *.json -> 冻结快照（能跑，但会打印过期警告 ✗）
  --extract-only     只抽取 + 报告，不调 API、不写文件
  --dry-run          走完整流程但不调 API、不写文件、不重编译
  --no-nss           完全不处理脚本字符串（只汉化 GFF）
  --no-ncs           不重编译 .ncs（脚本内文本不会在游戏里变中文）
  --no-var-assign    更保守：不把"字符串变量赋值"当显示文本
  --punct full|half  中文全角标点（默认）/ 英文半角
  --nwnsc / --install-dir / --extra-args   手动指定编译器与安装目录
  --yes              跳过确认
```

## 10. TLK 汉化与「更新后只翻增量」（PRC8 这类模组）

PRC8 的文本不在 `.mod` 里，而在一个 **TLK 字符串表**里。它经常更新，所以关键是"只翻增量"。

### 一次性准备：把已有对照存进记忆库（0 花费）

```powershell
cd C:\nwn-ee-l10n
python -m modl10n.tlk import-txt ".\prc8.txt" ".\prc8_zh.txt"
```

`prc8.txt` 是英文源、`prc8_zh.txt` 是中文，两者按 strref 一一对应。导入会：
- 按**英文原文内容**（而不是 strref 序号）存进 `modl10n\tm.sqlite`，与 Swordflight **共用同一个库**；
- **跳过记忆库里已存在的 key**，绝不覆盖你润色过的条目；
- 把「中文与英文相同」的条目（`PDK`、`UrP`、`== ac reserved ==` 这类**缩写代码/占位符**）
  也按"就该是英文"收录 —— 以后就不会再被送去 API 白花钱、也不会被模型改坏。

### PRC 更新后：一键增量汉化

```powershell
# 1) 先看不花钱的账：多少能白拿、多少要花钱
python "tlk tool.py" update "新版\prc8_consortium.tlk" "输出\prc8_consortium_zh.tlk" --dry-run

# 2) 真跑（先吃记忆库，只把没命中的送去翻译）
python "tlk tool.py" update "新版\prc8_consortium.tlk" "输出\prc8_consortium_zh.tlk"
#    Key 取自环境变量 DEEPSEEK_API_KEY；没有会提示输入，
#    直接回车 = 只用记忆库、不调用 API（0 花费）
```

输出会明确分三行：**记忆库命中（0 花费）/ API 新译 / 未译保持英文**，并自动读回校验。
写出用的是**外科式**写入：只重建字符串数据区、保留索引表其余字段（不碰声音长度等不明字段）。

实测（模拟一次 PRC 更新：200 条英文被改写 + 50 条全新）：

| 项目 | 结果 |
|---|---|
| 新版需要中文 | 29,676 条 |
| 记忆库命中（0 花费） | **29,426 条（99.2%）** |
| 真正需要翻译 | **250 条** |
| 写出后读回校验 | **0 不一致** ✅ |

### 顺带：TLK 编辑器（`tlk tool.py` 图形界面）

双击 `tlk tool.py` → 「工具 → AI 翻译未翻译条目」。现在它会**先查记忆库**，
弹窗会先告诉你「记忆库已有 N 条（0 花费）/ 需要调用 API M 条」，只对 M 条花钱。

### 术语统一（0 花费，实测把 128 组不一致清成 0 组）

```powershell
# 1) 生成术语统一表：默认取文件里的「多数派」，脚本里另有一批按 D&D 官方惯例的修正
python "prc8_术语统一.py"
#    -> prc8_术语统一表.tsv：英文术语 / 规范译法 / 被替换的变体 / 说明 / 范围 / 保护
#    可直接用 Excel 改「规范译法」列。另外两列是安全阀：
#      范围「仅词条」= 只改该词条本身（英文本身也是常用词时必须用它，如 Command / Orcish）
#      保护「邪恶阵营」= 替换时先遮蔽该片段（避免把规则术语也改掉）

# 2) 看会改多少（不写库、0 花费）
python -m modl10n.tlk unify --table ".\prc8_术语统一表.tsv" --dry-run
# 3) 应用（0 花费，改记忆库；改过的标 manual）
python -m modl10n.tlk unify --table ".\prc8_术语统一表.tsv"
# 4) 用记忆库重建 TLK（0 花费）—— 顺带把「同一英文、多种译法」的重复文本一起统一
python -m modl10n.tlk rebuild ".\PRC8汉化补丁\prc8_consortium.tlk" ".\prc8.txt" ".\新品.tlk"
```

`日光→昼明术`、`橡木棍→橡棍术`、`能量抗力→异能抗力`、`史诗武士→传奇武士`、
`洛山达/拉桑德→兰森德尔`、`苏妮→淑妮`、`西门→西门城`、`高等命令→高等命令术`

> 两条经验：①**批量替换前一定抽样看** —— 术语表审计里 `Bane` 报了 81 条，
