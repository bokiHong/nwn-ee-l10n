# 维护者：把源项目的进展同步到这个开源仓库

这个仓库是从一个**私有工作区**（`汉化\scripts\`）整理出来的公开副本。
源项目一直在动，所以需要一个可重复的同步流程 —— 否则公开版会慢慢落后。

> 本文是给**维护者**看的；普通使用者只需要 `tools/bootstrap.py` + `python -m l10n.selftest`。

---

## 什么时候要同步

| 信号 | 要同步什么 |
| --- | --- |
| 源项目加了新工具 / 新 service | 代码 |
| 源项目修了 bug、改了验收 | 代码 |
| 翻译记忆库 / 术语表增长 | 数据（`nwn-ee-l10n-data`） |
| README 里引用的验收项数变了 | 文档 |

**判据（务必做）**：同步后跑三档验收，**三档都必须 0 失败**：

```bash
python -m l10n.selftest          # 只克隆代码（未导入数据）
python tools/bootstrap.py --data ../nwn-ee-l10n-data/data
python -m l10n.selftest          # 导入数据后
```

完整环境（有真实模组 + TLK）另跑一次，环境变量见文末。

## 一、盘点差异

```bash
SRC=<源项目>\scripts
cd $SRC && find . -name "*.py" -o -name "*.bat" -o -name "*.md" | grep -v __pycache__ \
  | sed 's|^\./||' | sort > /tmp/src.txt
cd <本仓库> && find . \( -name "*.py" -o -name "*.bat" -o -name "*.md" \) \
  -not -path "./.git/*" | grep -v __pycache__ | sed 's|^\./||' | sort > /tmp/dst.txt

comm -23 /tmp/src.txt /tmp/dst.txt        # 源有、本仓库没有（新增）
comm -12 /tmp/src.txt /tmp/dst.txt | while read f; do
  cmp -s "$SRC/$f" "$f" || echo "  ~ $f"; done   # 两边都有但不同（更新）
```

**注意 `find` 的深度**：`l10n/services/*.py` 在 depth 3，用 `-maxdepth 2` 会漏掉一整层 ✗

## 二、哪些该同步、哪些不该

**该同步**：`l10n/`、`modl10n/`、`tools/`、顶层 `*.py`（GUI 与启动器）、`*.bat`、`modl10n/*.md`、
设计文档（放 `docs/`）。

**不该同步**（保持不开源）：

| 类别 | 例子 | 理由 |
| --- | --- | --- |
| 一次性构建脚本 | `_制作脚本/` | 与使用者无关，且常含个人路径 |
| 已被取代的旧流水线 | `dnd_crawl.py`、`dnd_mine.py`、`tob_audit.py`、`make_glossary.py`、`translate_tlk.py`、`import_tm.py`、`fix_terms_batch.py`、`probe_terms.py`、`mk_probe.py`、`check_*.py`、`diff_ch1*.py`、`verify_attribution.py` | 会被误当成"该走的流程"，实际入口是 `l10n` / `modl10n` |
| 数据与产物 | `tm.sqlite*`、`*.mod`、`*.tlk`、`*.hak`、`tmp/`、`module/` | `.gitignore` 已挡（红线） |
| 密钥 | `.api_key` | `.gitignore` 已挡 |

## 三、复制之后，**必须重打的开源化改造**

源项目的文件里带着"只在私有工作区成立"的假设。直接复制会把这些改造冲掉 ✗
`git diff` 只看得到改动、看不出哪些是"开源化"、哪些是"源项目新增"，所以要按这份清单逐项确认。

| 文件 | 必须保持的开源化改造 |
| --- | --- |
| `l10n/paths.py` | **本仓库独有，源项目没有** —— 绝不要被覆盖掉；它提供 `nwn_home()` / `nwn_sub()` / `nwn_find()`，统一 NWN 目录探测（`NWN_HOME` 环境变量优先） |
| `l10n/selftest.py` | ① 顶部 `CH1` 用 `L10N_TEST_MOD` 环境变量 + `HAS_CH1`；② `_skip()` / `_probe_data()` / `_check_data()` 三个助手；③ 依赖公开数据的断言一律走 `_check_data`；④ Sprint 2/3/5 缺私有资产时整段跳过；⑤ `main()` 里全新环境自动建空库。**源版新增 Sprint 时要把它也纳入守卫** |
| `l10n/selftest_gui_mod.py` | `CH1` / `SMALL` 用 `L10N_TEST_MOD` / `L10N_TEST_MOD_SMALL`；`cases` 列表在样本缺失时剔除依赖它的用例 |
| `l10n/selftest_gui_terms.py` | `skip()` 助手；依赖 PRC8 TLK / `prc8.txt` / 术语核对报告的用例改为跳过 |
| `l10n/tlk_audit.py` | `GAME_DIR = paths.nwn_sub("tlk")`，不再硬编码用户目录 |
| `rebuild_tlk_safe.py` | `NWN_TLK` / `NWN_EN_TLK` / `PRC8_EN_TXT` 环境变量 + `paths.nwn_sub("tlk")` |
| `l10n/repo/term_repo.py` | `export_json()` 自己 `makedirs`（源项目依赖调用方先建好目录） |
| `l10n/services/rebuild_service.py` | 新增文件最容易带回硬编码：`DEF_GAME_TLK` / `DEF_BASE_EN` 用 `NWN_TLK` / `paths.nwn_sub("tlk")`；`DEF_EN_TXT` / `DEF_OUT` 用 `SCRIPTS` 而不是 `ROOT`（开源布局下 `ROOT` 是仓库的父目录 ✗） |
| `汉化工作台.py`、`翻译流水线.py`、`adopt_terms.py` | 同样的目录层级假设：`ROOT = HERE`（开源布局里仓库根就是工作根）；`os.path.join(HERE, "..", "tmp", …)` → `os.path.join(HERE, "tmp", …)` |
| `modl10n/README.md`、`modl10n/新手上手.md` | 两处路径替换：`<源工作区>` → `C:\nwn-ee-l10n`；`C:\Users\<你>\Documents\Neverwinter Nights` → `%USERPROFILE%\Documents\Neverwinter Nights` |

**复制完立刻扫一遍**（这两条必须为空）：

```bash
grep -rn "lh134" --include="*.py" --include="*.md" --include="*.bat" . | grep -v "\.git/"
grep -rn '"\.\.", "tmp"' --include="*.py" . | grep -v "\.git/"
```

## 四、同步数据（另一个仓库）

```bash
python tools/export_data.py --db <源项目>\scripts\modl10n\tm.sqlite \
    --out ../nwn-ee-l10n-data/data --schema-out schema

rm -f modl10n/tm.sqlite*                       # 重建本仓库的中央库
python tools/bootstrap.py --data ../nwn-ee-l10n-data/data
```

**验收判据**：导入后的条数必须与源库**相等**。

```bash
python -c "import sqlite3;print(sqlite3.connect(r'modl10n/tm.sqlite').execute('select count(*) from tm').fetchone()[0])"
python -c "import sqlite3;print(sqlite3.connect(r'<源库>').execute('select count(*) from tm').fetchone()[0])"
```

导出逻辑上有两条**不能动**的规则（都踩过坑，见仓库 lesson）：

1. **带上原始 `key` 且导入时不许重算** —— 库里有 norm / raw 两种 key 算法写进来的行。
2. **「孤儿译文」不能过滤** —— `src` 为空但 `key`/`dst` 有效的行（实测 64 条）是
   "模组文本按 key 能查到译文、按 src 查不到"的原因；滤掉会让导入方看到假的未译缺口。

## 五、跑三档验收

```bash
# ① 只克隆代码（未导入数据）—— 把 tm.sqlite 挪走再跑
# ② 导入数据包后
python -m l10n.selftest

# ③ 完整环境（有真实模组 + PRC8 TLK 时）
export L10N_TEST_MOD='<...>\Swordflight - Chapter One.mod'
export L10N_TEST_MOD_SMALL='<...>\_erf_selftest.mod'
export PRC8_EN_TXT='<...>\prc8.txt'
export NWN_HOME='C:\Users\<你>\Documents\Neverwinter Nights'
python -m l10n.selftest
```

2026-10-12 实测：**42 / 70 / 102 项全过，0 失败**。项数会随源项目增长，README 里的数字要跟着改。

## 六、提交与推送

```bash
git add -A
git status --short          # 确认没有 sqlite / mod / tlk / api_key 混进来
git diff --cached --name-only | grep -Ei "sqlite|\.mod$|\.tlk$|api_key|__pycache__" \
  && echo "⚠ 有危险文件，停下！"
git commit -m "同步源项目进展：…"
git push origin main        # GitHub
```

⚠ **GitHub 在国内常连不上**（`Failed to connect ... 443` / `Connection was reset`）。
这是网络抖动、不是配置错 —— **重试几次**通常就成（2026-10-12 实测第 3 次成功）。

## 附：本仓库与源项目的布局差异（改代码时最容易踩的点）

| | 源项目 | 本仓库 |
| --- | --- | --- |
| 代码根 | `汉化\scripts\` | **仓库根**（原来的 `scripts` 摊平） |
| 工作区根 | `汉化\`（`scripts` 的父目录） | 就是仓库根 |
| 私有资产 | `汉化\module\`、`汉化\tmp\` | **不存在** —— 靠环境变量指向本机 |
| 术语源 | `tm.sqlite` 的 `term` 表 | 同（数据包导入） |
| 中央库位置 | `汉化\scripts\modl10n\tm.sqlite` | `<仓库>\modl10n\tm.sqlite`（已 gitignore） |

所以凡是源项目里写 `os.path.dirname(SCRIPTS)`（想拿工作区根）的地方，
在本仓库里**几乎都要改成 `SCRIPTS` 本身**。
